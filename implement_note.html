BRAMBLE RELEASE 2.1.0 - STATE MANAGEMENT ARCHITECTURAL MIGRATION (BLoC / CUBIT)

Implementation Note - Hệ Thống Bramble Novel Reader

1. Task

Chuyển đổi toàn diện kiến trúc State Management của ứng dụng Flutter Mobile Bramble từ Flutter Riverpod sang BLoC / Cubit (sử dụng flutter_bloc: ^8.1.6, equatable: ^2.0.5, bloc_test: ^9.1.7). Loại bỏ 100% Riverpod khỏi production codebase mà không làm thay đổi Backend API, Spring Boot backend, MySQL database hay Design System.

2. Nguyên Nhân & Mục Tiêu

  • Chuẩn hóa kiến trúc doanh nghiệp theo BLoC Pattern & Clean Architecture: phân định rõ ràng giữa Event, State, Cubit, BLoC, Repository và UI Presentation Layer.
  • Quản lý trạng thái bất biến (Immutable State) với Equatable, hỗ trợ testability cao và phân tách rõ luồng xử lý side-effects.
  • Điều hướng xác thực hoàn toàn tất định (Deterministic Auth Routing) bằng GoRouterRefreshStream(authBloc.stream), giải quyết triệt để rủi ro redirect loop.
  • Giữ nguyên 100% giao diện High-End Editorial / Literary design system, font chữ (Lora, Figtree), theme (Cream, Sepia, Night) và toàn bộ business logic.

BRAMBLE RELEASE 2.2.0 - STRONGLY-TYPED DOMAIN MODELS & DTO PARITY MIGRATION

Implementation Note - Hệ Thống Mô Hình Dữ Liệu Type-Safe (Domain Models)

1. Task

Xây dựng hệ thống Domain Models strongly-typed cho ứng dụng Flutter Mobile đồng bộ 1-to-1 với toàn bộ DTOs của Spring Boot Backend (backend/src/main/java/com/bramble/novel/dto/*). Nâng cấp toàn bộ Repositories và BLoCs/Cubits sang trả về và quản lý các đối tượng Model chuẩn hóa thay vì dùng Map<String, dynamic> thô, đồng thời tích hợp cơ chế dynamic operator [](String key) để đảm bảo 100% backward-compatibility với các Widget UI hiện tại.

2. Nguyên Nhân & Mục Tiêu

  • Khắc phục tình trạng sử dụng Map<String, dynamic> rời rạc gây khó khăn trong bảo trì, thiếu auto-complete và rủi ro runtime casting lỗi (ClassCastException / Null Safety).
  • Khớp hoàn toàn 1:1 với các DTOs phía Spring Boot: BookResponse, BookDetailResponse, ChapterResponse, ChapterDetailResponse, DiscoverResponse, LibraryItemResponse, StatsResponse, AuthResponse, UserPreferencesDto, ApiResponse<T>, PageResponse<T>.
  • Đảm bảo Zero-Breaking Changes: Tầng UI có thể truy cập vừa theo getter type-safe (ví dụ chapter.content, book.title) vừa qua cú pháp index operator chapter['content'], book['title'].

4. Logic Thay Đổi

  • 1-to-1 DTO Parity: Tất cả các trường dữ liệu từ Spring Boot backend (như viewsCount, readersCount, coinCost, isUnlocked, totalChapters, popularGenres, v.v.) đều được map chính xác.
  • Universal Index Operator Support: Mỗi model đều triển khai dynamic operator [](String key) ánh xạ các key JSON phổ biến và các alias cũ, loại bỏ nguy cơ runtime error ở các màn hình view kế thừa.
  • ActiveReadingModel Compatibility: Mở rộng ActiveReadingModel.operator [] (hỗ trợ bookTitle, author, coverUrl, percentage, pctText) và loại bỏ ép kiểu cứng as Map<String, dynamic>? tại home_screen.dart.
  • BookDetailState ChapterModel Sync: Cập nhật BookDetailLoaded.chapters từ List<Map<String, dynamic>> sang List<ChapterModel> tại book_detail_cubit.dart và chapter_list_screen.dart.
  • Comments Endpoint Alignment: Cập nhật endpoint tạo comment trong CommentsRepository sang POST /chapters/{chapterId}/comments đồng bộ với Backend Spring Boot CommentController và nâng cấp CommentModel hỗ trợ operator [].
